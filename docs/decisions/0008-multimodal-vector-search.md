# 0008 Multimodal Vector Search using BGE-VL-large

Date: 2026-06-18

## Status

Accepted

## Context

We need to retrieve relevant document figures (images) based on user text questions.
To achieve this, we can either:
1. Embed the visual description text generated by Qwen3-VL using BGE-M3.
2. Embed the images directly using a cross-modal (multimodal) visual-linguistic joint embedding model like BGE-VL-large.

Embedding visual descriptions has high dependency on the VLM description quality and misses raw visual semantic concepts. Joint-space models allow search directly on the visual elements.

## Decision

We decide to use **`BAAI/BGE-VL-large`** as the core multimodal embedding model.
- We will store image vectors in a new database table `document_images` with a 768-dimension vector column.
- Text queries will be encoded by the text-encoder of `BgeVisualizedEmbedder` to search both tables.
- CUDA GPU acceleration will be active to handle VLM workloads.

## Alternatives Considered

1. **Clip ViT-L/14**: Good multimodal model but has poor Vietnamese support and doesn't handle dense OCR elements or document layout structure concepts as well as BGE-VL.
2. **Text-only description embedding**: Lower footprint but loses direct image-to-text semantic associations.

## Consequences

Positive:
- Allows direct visual retrieval matching layout patterns and charts.
- Provides highly relevant visual citations.

Tradeoffs:
- Requires loading the `BAAI/BGE-VL-large` model directly via Hugging Face `transformers` (with `trust_remote_code=True`) and PyTorch.
- Larger memory footprint (~1.2 GB model weight and GPU VRAM).
